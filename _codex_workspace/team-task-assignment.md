# 团队任务分工（第一版）

## 总体目标

把现有系统升级为“蓉城医枢智能用药闭环平台”：药品查询、图片识别、知识库问答、药物冲突检查、用药提醒、服药打卡和医护协同形成闭环。

## 角色分工

### 你：神经网络与 AI 负责人

第一阶段只承诺一个可验收主线：药盒图片上传 → OCR 提取药品名称/规格/有效期 → 返回结构化结果。

后续扩展：

1. 药品图片分类或检测（YOLO/分类模型二选一，先不要同时训练多个模型）。
2. OCR 字段提取与后处理。
3. 服药依从性风险预测模型。
4. 模型训练集、验证集、测试集、训练曲线、混淆矩阵和指标报告。
5. 为每次识别保留模型版本、置信度和原始图片哈希，便于答辩和追溯。

你的代码放在 `ai-service/`，不要把训练代码塞进 Spring Boot 的 `AiService.java`。

### 队友一：安卓与移动端

1. 先完成响应式页面和移动端导航。
2. 再使用 PWA 或 Capacitor 打包 Android APK。
3. 优先实现今日用药、服药打卡、图片上传、识别结果确认和提醒通知。
4. 不直接修改数据库；只依赖已确认的后端 API。

### 队友二：后端、药品数据和知识库接口

1. 设计并实现药品主数据、药品说明、来源信息和药物冲突数据。
2. 增加药品搜索、详情、冲突检查和用药计划接口。
3. 统一数据库表名 `tb_` 前缀、字段命名和外键策略。
4. 实现知识库文档的导入元数据接口，保留来源、版本、审核状态和更新时间。
5. 为 AI 服务预留图片识别和风险预测代理接口。

数据库改动必须同步更新 `backend/src/main/resources/schema.sql` 和演示数据，不允许只在本地数据库手工改表。

### 队友三：前端系统改装与联调

1. 将药品百科、识别结果、知识库问答和风险提示做成独立组件。
2. 新增页面优先放在 `src/features/`，公共组件放在 `src/components/`。
3. 负责前端 API 封装、加载态、错误态、空数据态和权限提示。
4. 负责多角色联调和回归测试，不直接改 AI 模型训练代码。

## 共同验收标准

- 不能提交密钥、数据库文件、日志和 `node_modules`。
- 不能把模型的训练集准确率当作最终效果，必须报告独立测试集指标。
- 医疗回答必须展示知识来源或明确提示“需要咨询医生”。
- 所有新增接口至少提供一个成功场景和一个失败场景的测试说明。
